# Task ID: 13
# Title: Migrate Global CSS to Tailwind Utility Classes
# Status: pending
# Dependencies: None
# Priority: high
# Description: Extract and migrate styles from globals.css to inline Tailwind CSS classes across all components, following Tailwind v4 best practices.
# Details:
This task involves a systematic migration from global CSS to Tailwind utility classes:

1. **Audit Phase**:
   - Create an inventory of all styles in src/app/globals.css
   - Categorize styles into: layout, typography, colors, animations, responsive styles, etc.
   - Identify which styles have direct Tailwind equivalents and which might need theme extensions
   - Audit which components and pages use each global class (e.g., .wrap, .page-content, .post, .post-header, .meta, .post-content, .site-header, .site-footer, .social-icons, etc.)

2. **Migration Planning**:
   - Create a mapping document that shows each global CSS rule and its Tailwind equivalent
   - Reference the mapping document in docs/globals-css-to-tailwind-mapping.md
   - For each component/page, create a migration checklist mapping each global class to its Tailwind v4 utility equivalent
   - Determine if any styles need to be maintained as CSS variables in the Tailwind config

3. **Implementation**:
   - Update the Tailwind config to include any necessary theme extensions
   - Begin migration with the blog post page ([slug]/page.tsx), demonstrating how to replace each global class with the mapped Tailwind v4 utilities inline
   - Systematically update each component to use Tailwind classes instead of relying on globals.css
   - Repeat for other key components (header, footer, etc.), removing global CSS as each is migrated
   - For complex styles without direct Tailwind equivalents, use the @apply directive in component-specific CSS modules
   - For repeated patterns, consider creating Tailwind component classes in the config

4. **Cleanup**:
   - Remove migrated styles from globals.css
   - Verify no component styling breaks after removal
   - Ensure that any remaining global styles are only those that cannot be represented with Tailwind v4 utilities

Ensure backward compatibility throughout the migration process by implementing and testing changes incrementally.

# Test Strategy:
To verify successful migration:

1. **Visual Regression Testing**:
   - Take screenshots of key UI components before migration
   - Compare with post-migration screenshots to ensure visual consistency
   - Test across multiple viewport sizes to verify responsive behavior
   - Test visual parity and responsive behavior after each migration step

2. **Component Testing**:
   - Create a checklist of components affected by globals.css
   - Verify each component renders correctly with Tailwind classes
   - Test component states (hover, focus, active, disabled) to ensure all styles are properly migrated

3. **Browser Compatibility**:
   - Test in Chrome, Firefox, Safari, and Edge to ensure cross-browser compatibility
   - Verify mobile rendering on iOS and Android devices

4. **Performance Checks**:
   - Compare bundle sizes before and after migration
   - Measure CSS specificity improvements
   - Verify reduced CSS file size after removing globals.css

5. **Validation Steps**:
   - Run the application with globals.css completely removed to verify no styling dependencies remain
   - Use browser dev tools to confirm styles are applied via Tailwind classes
   - Verify no unexpected CSS cascading issues occur
   - Check for any console errors related to missing styles
